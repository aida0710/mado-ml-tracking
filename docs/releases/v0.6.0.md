mado S3 Data Catalogとの連携を作り直しました。DataLineageの連携（データセットの取り込みと、Runの記録の送信）を外し、接続はProjectごとから全体で1つになります。接続すると、`s3://`の場所をmado S3 Data Catalogの画面で開けます。接続にはmado S3 Data Catalog v0.6.0以降が要り、**更新のあと、全体管理者が接続し直します**。DBの更新は前の版のAPIと両立せず、戻すにはバックアップからの復元が要ります。

## 変更点

- **DataLineageの連携の削除**: mado S3 Data CatalogがDataLineageを外したので、データセットの取り込みと、Runの記録の送信を無くしました。取り込み済みのデータセットバージョンはそのまま残り、Runの入力に使えます。送信の滞留のアラート（`plugin.delivery_stalled`）は発生しなくなります。
- **接続を全体設定の「Plugins」へ**: Projectごとの「連携」の画面を無くし、全体設定 → 全体管理に「Plugins」を作りました。入力はURLとアクセストークンだけです。URLは画面のもので、APIは同じURLの下を呼びます。「接続」を押すと接続を確かめ、通ったときだけ保存します。有効・無効の切り替えはありません。扱えるのは全体管理者です。
- **Projectのサイドバーに「全体設定」**: サイドバーの下端から全体設定へ行けます。
- **ストレージ接続**: mado S3 Data Catalogに登録したS3の接続先（オンプレミスのS3、AWSなど）を、接続・確認のときに読んで覚えます。接続済みのサイトでは、`s3://`のURIを登録するときにストレージ接続が必須です。画面では、データセットとモデルのバージョンを作る画面でURIに`s3://`を入れると「ストレージ接続」の欄が出ます。Jobの出力の宣言、Taskの出力の登録、MLflowのクライアントが作るバージョンは、今までどおり作れます。
- **mado S3 Data Catalogで開く**: ストレージ接続を持つバージョンのURIの横に、mado S3 Data Catalogのその場所の画面へのリンクが出ます。ストレージ接続はリンクの行き先を決めるだけで、実行先がどのS3から読むかは変わりません。
- **URLをS3のURIに直す**: 登録の画面にmado S3 Data Catalogの画面のURL（「Web URLをコピー」の値）を貼ると、`s3://`のURIを示し、押すとURIとストレージ接続が入ります。
- **容量**: mado S3 Data Catalogが測ったストレージの容量は、「Plugins」の画面で全体管理者が見ます。Projectの画面には出ません。
- **API**: `/api/projects/:p/plugins*`を無くし、`/api/admin/plugins/data-catalog`（GET・PUT・DELETE、`/capacity`）にしました。Projectを読める人向けに`GET /api/projects/:p/data-catalog`（画面のURLとストレージ接続の名前・種類）を足しました。DatasetVersionとModelVersionの応答に`dataCatalogStorageConnectionId`（無ければnull）が増えます。エラーの`code`は`plugin_*`から`data_catalog_*`に変わります。
- **Python SDK**: `register_dataset`・`register_model`に`data_catalog_storage_connection_id`を、ストレージ接続の一覧を引く`data_catalog`を足しました。`register_dataset`の`external_ref`は無くなりました。
- **依存の更新**: honoと@hono/node-serverを、`npm audit`の指摘が無い版へ上げました。

使い方は[Plugins](https://github.com/aida0710/mado-ml-tracking/blob/v0.6.0/docs/plugins.md)にあります。

## 互換性と更新手順

更新前にDBをバックアップしてください。このリリースの移行（073〜076）は、当てたあと前の版へ戻すにはバックアップからDBを復元します。v0.5.0〜v0.5.4から更新するときは、[配布物で更新する](https://github.com/aida0710/mado-ml-tracking/blob/v0.6.0/deploy/release/README.md)手順で入れ替えます。

v0.4.0以前から更新するときは、先に[v0.5.0の更新手順](https://github.com/aida0710/mado-ml-tracking/blob/v0.5.0/docs/releases/v0.5.0.md)を済ませます。

1. **mado S3 Data Catalogより先に、この製品を更新します。** v0.5.4までは、mado S3 Data CatalogのDataLineageへ取り込みと送信をします。mado S3 Data Catalogをv0.6.0へ上げる前に、この版へ上げます。
2. **APIとプレビュー用workerを止めてからDBを更新します。** 移行は前の版のAPIと両立しません。更新手順の「4. 切り替える」で、先に`docker compose stop api preview`を実行します。
3. **全体管理者が接続し直します。** Projectごとの接続は引き継ぎません。移行074が、保存していたアクセストークンと確認の結果を消します。mado S3 Data Catalogをv0.6.0以降へ上げたあと、全体設定 → 全体管理 → 「Plugins」で、URLとアクセストークンを入れて接続します。アクセストークンには、Capacityの読み取りと、使うストレージ接続（mado S3 Data Catalogの接続）を許可します。接続しなくても、実験管理は今までどおり使えます。
4. **`s3://`のURIを登録しているスクリプトを確かめます。** 接続したあとは、API・Python SDKで`s3://`のURIを登録するときに、ストレージ接続のID（`dataCatalogStorageConnectionId`、SDKは`data_catalog_storage_connection_id`）が要ります。無いと422 `data_catalog_storage_connection_required`で断ります。Jobの中のコードがSDKで登録している場合も同じです。v0.5.4までのPython SDKはIDを送れないので、SDKを更新します。未接続のサイトでは、今までどおり登録できます。
5. **APIを直接呼んでいるものを直します。** `/api/projects/:p/plugins*`は無くなりました。データセットの登録の`externalRef`は、`null`だけ受け付けます（v0.5.4までのPython SDKが送る値）。値のある`externalRef`は422で断ります。

設定の名前の変更はありません。アクセストークンを暗号化する鍵は、今までどおり`MMT_PLUGIN_SECRET_KEY`です。

以前のデータの扱いは次のとおりです。

- Projectごとの接続（`plugin_connections`）: 行は残りますが、読みません。
- 取り込んだデータセットバージョン: そのまま残ります。外部参照（`externalRef`）は値を表示するだけです。
- 送ったRunの記録（`plugin_outbox`）: 行は残ります。読む画面とAPIはありません。

開発と運用の土台とAPIの形を、兄弟製品のMadoにそろえました。監査ログの値の名前を変え、Webのnginxを非rootで動かし、APIはビルドしたJavaScriptで動かします。APIのエラー応答は英語の文とcodeになり、ヘルスチェックは`GET /healthz`に、API tokenの前置きは`mado_mt_`（Job tokenは`mado_mtj_`）になりました。**発行済みのAPI tokenはすべて使えなくなるので、更新後に発行し直してください。**

## 変更点

### API

- 監査ログ（AuditEvent）の`outcome`の`failed`を`failure`に、接続元の項目`ip`を`ipAddress`に変えました（DBの列は`ip_address`）。`GET /audit-events`・`GET /projects/:p/audit-events`の`outcome`の絞り込みも`failure`を使います。既存の記録はDBの更新（`071_audit_failure_and_ip_address.sql`）で書き換えます。
- `docs/openapi.json`と`GET /api/openapi.json`の`info.version`が、契約の版（`0.1`）ではなくアプリの版になりました。
- 独自APIのエラー応答を`{"error": <英語の文>, "code": <理由の名前>}`にそろえました。`error`は今まで日本語でしたが、英語になります。文に入る値（足りないscope、parameter名、上限など）は`error`・`code`の横の項目にも入ります（例: `scope_required`の`scope`・`purpose`、`invalid_request`の`fields`）。codeの一覧は`@mmt/contracts`の`API_ERROR_CODES`で、OpenAPIのエラー本文のschema名は`ApiError`から`ApiErrorBody`に変わりました。MLflow互換APIは今までどおり`{"error_code", "message"}`で、`message`が英語になります。
- Madoと同じ意味のcodeは同じ名前にしました。

  | 旧 | 新 |
  | --- | --- |
  | `insufficient_scope` | `scope_required` |
  | `invalid_parameter_value`（Runの検索式・cursorなど） | `invalid_request` |
  | `resource_already_exists` | `already_exists` |
  | `invalid_range` | `range_not_satisfiable` |
  | `last_global_admin` | `last_active_admin` |
  | `local_account_required` | `local_credential_unavailable` |
  | `scope_exceeds_issuer` | `token_authority_exceeded` |
  | パスワード変更で現在のパスワードの誤り: 401 `invalid_credentials` | 400 `incorrect_password` |

- Sweepの探索空間とearly_terminateの誤り（`sweep_space_invalid`・`sweep_early_terminate_invalid`）は、`reason`（`values_empty`・`range_order`など）と`parameter`などの項目で理由を示します。
- ヘルスチェックの`GET /health`と`GET /api/health`をやめ、`GET /healthz`（`/api`の外、認証なし）が`{"status":"ok"}`を返すようにしました。DBに届かなければ503 `database_unavailable`です。
- API token（個人・Service Account・worker・launcher）の値は`mado_mt_`、Job tokenは`mado_mtj_`で始まります。認証はこの形の値だけを受け付け、`mmt_`・`mmtj_`で始まる値は401 `invalid_token`です。一覧に出す先頭は16文字（前置きと8文字）になりました。

### Web

- 画面の応答に、Content-Security-Policy、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`を付けます。外部のサイトから画面を読み込むことはできません。
- APIのエラーは、日本語の画面ではcodeから訳した文を出します。訳の無いcodeはAPIの英語の文を出し、`invalid_request`などの理由の幅が広いcodeは日本語の文のあとにAPIの英語の文を括弧で添えます。英語の画面はAPIの英語の文を出します。

### コンテナ・Compose

- Webのイメージは`nginxinc/nginx-unprivileged`になり、nginxはroot以外で動きます。コンテナの中で待ち受けるportは80から8080に変わりました。ホスト側（`127.0.0.1:5182`）は変わりません。
- APIとプレビュー用workerのイメージは、TypeScriptをビルドしたJavaScriptを`node`で動かします。イメージにはTypeScriptのソースとビルドの道具が入りません。`npm run db:migrate -w @mmt/api`などのコマンドは今までどおり使えます。
- 全イメージのベースイメージをdigestで固定しました。
- `compose.yml`にproject名（`name: mado-model-tracking`）を入れました。展開先のディレクトリ名にかかわらず、同じコンテナとvolumeを使います。
- `api`にヘルスチェック（`GET /healthz`）を付け、`web`は`api`がhealthyになってから起動します。Webのnginxとedgeのrunner用nginx（`deploy/edge/runner-api.conf.template`）は`/healthz`もAPIへ渡します。edgeでは今までの`/api/health`と同じく、Job tokenのあるrunnerにだけ答えます。

### SDK・worker・launcher

- `mado-tracking-worker doctor`とコンピュータの接続確認は、`MMT_API_URL`の`/api`を外した`/healthz`でAPIへの到達を確かめます。
- workerとrunnerは`mado_mtj_`で始まるJob tokenだけを受け付けます。v0.4.0までのworker・launcherは新しいAPIが発行するJob tokenを受け付けないので、APIと一緒に更新してください。

### そのほか

- Apache License 2.0のLICENSEとNOTICEを付けました。配布物にも入ります。

## 互換性と更新手順

更新前にDBをバックアップしてください。

1. Webのportを書き換えている場合（`compose.override.yml`の`ports`など）は、コンテナ側の番号を80から8080へ直します。例: `'0.0.0.0:80:80'`→`'0.0.0.0:80:8080'`。
2. v0.4.0までの配布物（bundle）から入れた環境は、Composeのproject名が展開先のディレクトリ名（例: `mado-ml-tracking-v040`）になっています。`docker compose ls`で今の名前を確かめ、`.env`に`COMPOSE_PROJECT_NAME=<その名前>`を書いてから更新します。書かないと新しい空のvolumeで起動します。リポジトリを`mado-model-tracking`というディレクトリに置いて動かしている環境は、そのままで同じ名前です。
3. 動いているJobを終わらせるか止めます。DBの更新（072）でJob tokenも失効するので、動いたままのJobはAPIへ記録できなくなります。
4. APIとプレビュー用workerを止め、新しいイメージでDBを更新してから（`071_audit_failure_and_ip_address.sql`、`072_token_prefix.sql`）、新しいAPI・プレビュー用worker・Webを起動します。071は監査ログの列名を変えるので、v0.4.0のAPIとは両立しません。Webのコンテナも入れ替えてください。
5. 072は、発行済みのAPI tokenとJob tokenをすべて失効させます（監査ログの`token.revoke`に、`details.reason`が`token_prefix_changed`の記録が残ります）。使っていたものは発行し直して差し替えます。
   - 個人のtoken・Service Accountのtoken: ［プロジェクト設定］の［API tokenを発行］かService Accountの画面で、同じ用途・scopeで発行します。SDK・MLflowの`MMT_API_TOKEN`・`MLFLOW_TRACKING_TOKEN`、学習のジョブが読むenv file、CIの設定などを新しい値に替えます。tokenを秘密の管理の仕組みに置いている場合は、そこに入れ直します。
   - worker: Service Accountでworker用のtokenを発行し、`mado-tracking-worker install --token-file`（Composeの`worker`は`MMT_WORKER_TOKEN_FILE`、既定は`var/worker-token`）で差し替えます。
   - launcher: 全体管理の「ランチャー」で各launcherの［tokenを作り直す］を押し、`launcher.toml`の`token_file`が指すファイルを新しい値に差し替えます。
6. ヘルスチェックを`/health`か`/api/health`で見ている監視は、`/healthz`に直します。Webの`127.0.0.1:5182/healthz`でも確かめられます。
7. APIのエラーの`error`の文や、上の表の旧いcodeを見ているスクリプトは、新しいcodeで判定するように直します。
8. 監査ログをAPIで読んで`outcome`の`failed`や`ip`を見ているスクリプトは、`failure`と`ipAddress`に直します。
9. Composeを使わずにソースから動かしている場合は、`npm run build -w @mmt/api`でAPIをビルドしてから、`npm run db:migrate -w @mmt/api`・`npm run start -w @mmt/api`を実行します。

worker・launcher・SDKは、Job tokenの前置きとヘルスチェックの経路が変わったので、APIと同じv0.5.0にそろえてください。

## 配布物

Linux amd64/arm64向けに、Web、API、プレビュー用worker、実行worker、サイトlauncherの5種類をGHCRで配布します。イメージ名は`ghcr.io/aida0710/mado-ml-tracking-{web,api,preview,worker,launcher}:v0.5.0`です。添付の`mado-ml-tracking-v0.5.0.tar.gz`には、イメージをdigestで固定したCompose、設定例、導入手順、LICENSE・NOTICEが入っています。SHA-256のチェックサムとビルド証明も添付します。

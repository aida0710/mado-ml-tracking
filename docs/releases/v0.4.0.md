古い版のworker・launcher・SDK・データを受け付けるために残していた扱いを削除しました。残っていた古い形のデータは、DBの更新（069・070）で今の形へ移します。

## 変更点

### API

- Run一覧`GET /projects/:p/runs`を削除しました。Runの一覧は`POST /projects/:p/runs/search`を使います。
- Dataset一覧・Artifact一覧・Job一覧などのqueryは、知らない条件を422 `invalid_request`で拒否します。省略時の既定値は変わりません。
- MLflow互換のモデルバージョン検索は、MLflowに無い`version`と`attributes.`を受け付けません。`version_number`、`attribute.`、前置きなしの属性名を使います。
- 旧方式のMado連携（`kind=legacy`、移行待ちの接続、移行完了API）を削除しました。
- コンピュータの所有者（`ownerUserId`）とCodeVersionの`runtime`を必須にしました。

### worker・launcher・SDK

- workerは`workerInfo`（version・hostname・parallelJobs・sshFiles・capabilities）を必ず送ります。送らないworkerのclaimは拒否します。
- コンテナの`result.json`と接続確認の結果は、version 2だけを受け付けます。pathで宣言したDatasetには`digest`を書きません（ファイルから計算します）。
- worker CLIはサブコマンドが必須です（`mado-tracking-worker run [--once]`）。
- 古いAPIに合わせて送る項目を減らす扱いを削除しました。worker・launcher・SDKはAPIと同じ版を使ってください。
- SDKの`register_model(name=...)`を削除しました（`model_name=`を使います）。`register_code`・`create_code_version`は`runtime`が必須です。

### 設定

- `OIDC_ADMIN_GROUP`と`DATABASE_URL`を削除しました。どちらかが設定されているとAPIは起動しません。`OIDC_ROLE_MAPPING_JSON`と`MMT_DATABASE_URL`を使います。
- `OIDC_ROLE_MAPPING_JSON`が無いとき、`mmt-admins`を全体管理者にする既定はなくなりました。SSOで全体管理者を決めるには対応表が必要です。

## 互換性と更新手順

更新前にDBをバックアップしてください。

1. `.env`から`OIDC_ADMIN_GROUP`と`DATABASE_URL`を消します（`OIDC_ADMIN_GROUP`を使っていた場合は`OIDC_ROLE_MAPPING_JSON`へ移します）。
2. APIを止め、新しいイメージでDBを更新してから（`069_require_current_protocol.sql`・`070_require_computer_owners.sql`）、新しいAPIを起動します。069は今の版のAPIと両立しません。
   - 069は、旧方式のMado連携の接続と、配送先を確定できない送信待ちのイベントを消します（DatasetVersionのURI・digest・来歴は残します）。接続確認の結果をversion 2へ、S3の保存先の`multipartEnabled`を明示値にし、workerの情報が欠けたpresenceは、そのleaseを失効させてから消します。
   - 070は、所有者のいないコンピュータに、成功した作成の監査記録が1人を指すときだけ所有者を補います。所有者を決められないコンピュータや設定の欠けたsiteが残っていると、更新は止まり、DBは何も変わりません。前の版で所有者を設定するかsiteを直してから、もう一度更新してください。
3. worker・launcher・SDKをこの版へ更新します。

Mado連携は引き続きMado v0.2.1以降で動きます。

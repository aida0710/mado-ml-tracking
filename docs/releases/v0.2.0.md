mado S3 Data Catalogとの連携を、アクセストークン1本で設定できるようになりました。許可するNamespaceは入力せず、Madoから自動で取得します。あわせて、来歴（Lineage）を既存の記録を書き換えずに補う機能と、モデルごとの来歴の表示を追加しました。

## 変更点

### Mado連携

- 参照用・送信用・容量取得用の3つのキーを、Madoのアクセストークン1本にまとめました。「許可Namespace」の入力欄はなくなりました。
- 検索と取り込みのたびに、Madoの`/api/mado/access-token`からトークンの許可範囲を読みます。Madoでトークンの許可Namespaceを変えても、連携の設定を保存し直す必要はありません。全Namespaceを許可したトークンでは、Namespaceを指定せずに1回で検索します。
- ［接続を確認］で、許可されている操作・許可Namespace・有効期限を画面に表示します。DataLineageの読み取りか送信を許可していないトークンや、「RunのNamespace」を許可していないトークンは、Runを送って失敗する前にここで理由を示して断ります。
- 容量メトリクスは、確認時のトークンに容量の読み取りがある場合だけ表示します。

### 来歴（Lineage）

- 既存のRun・バージョンを書き換えずに、データ・モデル・Runの関係を追記するAPIを追加しました。参照と、学習・生成の関係を区別します。
- モデル版の詳細と一覧から、そのモデルの祖先と子孫だけを表示できます。全体の図と既存の検索は従来どおりです。

## 互換性と更新手順

更新前にDBをバックアップし、**新しいAPIを起動する前に、新しいイメージでDBを更新してください**（`066_lineage_relation_additions.sql`と`067_mado_access_token.sql`）。

- **Mado連携を設定している場合:** v0.1.0で保存した参照用・送信用・容量取得用のキーは使われなくなり、「未設定」と表示されます。3つのキーは1つにまとめられないため、Madoでアクセストークンを発行し、［Madoの接続設定］で入れ直してから［接続を確認］を押してください。暗号化して保存した以前の値はDBから消しません。
- **Mado側はv0.2.1以降が必要です。** `/api/mado/access-token`の無いMadoへの接続確認は、「Madoを更新してください」という理由で止まります。
- **APIの変更:** 連携の`credentials`は`{accessToken}`だけになり、`config`から`namespaces`を外しました。`POST /api/projects/:p/plugins/:id/check`は`PluginConnection`を返します（以前は`PluginManifest`）。

## 配布物

Linux amd64/arm64向けに、Web、API、プレビュー用worker、実行worker、サイトlauncherの5種類をGHCRで配布します。イメージ名は`ghcr.io/aida0710/mado-ml-tracking-{web,api,preview,worker,launcher}:v0.2.0`です。添付の`mado-ml-tracking-v0.2.0.tar.gz`には、イメージをdigestで固定したCompose、設定例、導入手順が入っています。SHA-256のチェックサムとビルド証明も添付します。

[ドキュメント](https://aida0710.github.io/mado-ml-tracking/)の[Mado連携](https://aida0710.github.io/mado-ml-tracking/admin/plugins)に、新しい設定手順があります。

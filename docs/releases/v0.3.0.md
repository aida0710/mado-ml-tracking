APIトークンから、トークンの発行・失効、Service Accountの管理、全体の監査ログ、ユーザー管理を使えるようになりました。あわせて、トークンまわりの古い形式の受け付けをやめ、残っていた古い形式のトークンはDBの更新で失効させます。

## 変更点

### トークンから使える操作

- scopeに`tokens:manage`・`audit:read`・`users:manage`を追加しました。`admin`はこの3つを含みません。名前を指定して付けたトークンだけが持つので、これまでのトークンでできることは増えません。
- `tokens:manage`を持つトークンは、APIでトークンの発行・失効と、Service Accountの作成・変更・トークン発行ができます。扱えるのは、呼び出したトークンのscope・Project・有効期限の範囲に収まるトークンだけです（範囲外は403 `scope_exceeds_issuer`・`project_forbidden`・`token_outlives_issuer`）。
- `audit:read`と`users:manage`は、全体管理者がProjectを指定せずに発行するトークンだけが持てます。全体の監査ログは`admin`と`audit:read`、ユーザー一覧は`admin`と`users:manage`で読めます。ユーザーの作成・変更・一時パスワードの発行には、すべてのscopeが要ります。
- 自分のパスワード変更、コンピュータの自分の設定、アーカイブしたProjectの完全な削除は、引き続きブラウザだけで行えます。

### 古い形式の扱いの削除

- 個人向けのトークン発行（`POST /api/tokens`）から`kind`の指定を外しました。種別は所有者で決まります（人は`personal`、Service Accountは`service`）。`kind`を送ると422になります。
- `TokenSummary`の`legacy`を削除し、`tokenPrefix`を必須にしました。画面の「旧形式」表示もなくなりました。
- 設定`MMT_TOKEN_MAX_LIFETIME_DAYS`は読まなくなりました。期限を省略したトークンの既定日数は`MMT_TOKEN_DEFAULT_LIFETIME_DAYS`だけで決まります。

## 互換性と更新手順

更新前にDBをバックアップし、**新しいAPIを起動する前に、新しいイメージでDBを更新してください**（`068_revoke_legacy_tokens.sql`）。

- 068は、人が所有するservice token（Service Account導入前の形式）と、先頭12文字を保存する前に発行したトークンを失効させます。理由は監査ログの`token.revoke`の`details.reason`に残ります。これらを使っていたworker・SDK・スクリプトは、Service Accountか個人のトークンを発行し直して差し替えてください。
- `.env`で`MMT_TOKEN_MAX_LIFETIME_DAYS`を使っている場合は、値を変えずに`MMT_TOKEN_DEFAULT_LIFETIME_DAYS`へ名前を変えてください。変えないと既定の365日になります。
- `POST /api/tokens`に`kind`を送っているクライアントは、その項目を外してください。

Mado連携は引き続きMado v0.2.1以降で動きます。

groupsや`email_verified`を送らないIdP（Cloudflare AccessのGoogle連携など）でも、SSOでログインできるようにしました。足した設定はどれも既定では無効で、設定を変えなければloginの動きは変わりません。DBの移行はありません。

## 変更点

- **IdP側で入れる人を決める**: `MMT_OIDC_REQUIRE_ALLOWED_GROUP=false`にすると、groupを見ずに、loginできる人をIdPのポリシーだけで決めます。このとき`MMT_OIDC_ALLOWED_GROUPS`と`MMT_OIDC_ROLE_MAPPING_JSON`の対応表は空にします。groupが書いてあると、そこで絞れていると読み違えるので、APIは起動しません。既定は`true`で、今までどおり`MMT_OIDC_ALLOWED_GROUPS`が必須です。全体管理者は「全体管理」→「ユーザー」で付け外しします。
- **emailで人を見分ける**: `MMT_OIDC_IDENTIFY_BY_EMAIL=true`にすると、ユーザーをemailで見分けます。
  - まだ結び付いていないSSOのidentityは、emailが一致するユーザー（全体管理者や、別のIdPで入っていたユーザーも）へ結び付けます。同じemailのユーザーが複数いれば`ambiguous_email`で拒否します。
  - IdPが`email_verified`を送らないときは、emailを確認済みとして扱います。IdPが`false`と送ったときは上書きしません。`email_verified`を送らないIdPでこの設定が無いと、`email_not_verified`で拒否します。
  - IdPのemailを信用できるときだけ有効にします。`MMT_OIDC_AUTO_LINK_VERIFIED_EMAIL`とは同時に使えません。
- **許可するemailのドメイン**: `MMT_OIDC_ALLOWED_EMAIL_DOMAINS`（カンマ区切り）に書いたドメインの、確認済みのemailの人だけを通します（`email_domain_not_allowed`）。`MMT_OIDC_IDENTIFY_BY_EMAIL=true`のときは必須です。IdPのポリシーが誤って広げられても、ここで止まります。
- **IdPのログアウト**: `MMT_OIDC_LOGOUT_URL`に、ログアウトのときにブラウザで開くIdPのURLを指定できます。SSOのsessionのときだけ開きます。`end_session_endpoint`を出さないIdPで使います。
- **API**: `POST /api/auth/logout`の応答を、本文の無い204から、200の`{ "idpLogoutUrl": string | null }`に変えました。値があるのは、SSOのsessionで`MMT_OIDC_LOGOUT_URL`を指定したときだけです。
- **依存の更新**: 勧告の出ている開発用の依存、Pythonのロックファイル（`python/uv.lock`）のcertifiとPillow、ドキュメントサイトのviteを更新しました。

設定の一覧は[`docs/operations.md`](https://github.com/aida0710/mado-ml-tracking/blob/v0.6.2/docs/operations.md)、画面での使い方は「SSO」の管理者向けのページにあります。

## 互換性と更新手順

v0.6.1からは、イメージを入れ替えるだけで更新できます。DBの移行と、Composeの変更はありません。[配布物で更新する](https://github.com/aida0710/mado-ml-tracking/blob/v0.6.2/deploy/release/README.md)手順で入れ替えます。

v0.6.0より前から更新するときは、先に[v0.6.1の更新手順](https://github.com/aida0710/mado-ml-tracking/blob/v0.6.1/docs/releases/v0.6.1.md#互換性と更新手順)を済ませます。

`POST /api/auth/logout`を直接呼んでいて、応答が204であることを確かめているものは、200も成功として扱うように直します。

別のIdPへ移るときは、次の順で進めます。

1. 新しいIdPにこの製品のclientを作り、戻り先に`<MMT_PUBLIC_URL>/api/auth/callback`を入れます。
2. 既存のユーザーのemailを、新しいIdPが送るemailにそろえます。そろえたユーザーは初めてのSSOで同じユーザーへ結び付き、全体管理者の権限とProjectのメンバーもそのまま残ります。
3. `MMT_OIDC_ISSUER_URL`・`MMT_OIDC_CLIENT_ID`・`MMT_OIDC_CLIENT_SECRET`を新しいIdPの値にし、上の設定を足してAPIを作り直します。

sessionの再確認は、UserInfoとrefresh tokenでの更新が通るかで判断します。新しいIdPにはrefresh tokenを出す設定をしてください。
